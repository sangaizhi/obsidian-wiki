### 一、垃圾收集器如何判断对象可以被回收
#### 1.1 引用计数法
       引用计数法的思想是这样的：给对象增加一个引用计数器，每当有一个地方引用它时，计数器的值就加1；当引用失败，计数器的值就减1；当计数器的值为0，就表示这个对象不能再被使用。
       引用计数法的实现简单，判断效率也很高效。但是，JAVA并没有使用这种方法，因为引用计数法很难解决对象之间相互引用的问题。

#### 1.2 根搜索算法
       根搜索算法的基本思路就是通过一系列的名为"GC Roots"的对象作为起始节点，并从这些节点开始向下搜索，搜索锁走过的路径称为引用链，当一个对象到 GC Root 没有任何引用链向连（从图上讲就是说这个节点到GC Root不连通）时，则表示这个对象时不可用的，那么这是就表示这个对象是可被回收的。
       在Java中，可以作为GC ROot是的对象有以下几种：
       1：虚拟机栈（栈针中的本地变量表）中引用的对象；
       2：方法区的类静态属性引用的对象；
       3：方法区中常量引用的对象
       4：本地方法栈中JNI(native方法)的引用的对象

### 二、对象的回收
        在说对象的回收之前，我们需要了解一些关于引用的点，在大体上，引用可以分为以下几类：
        1、强引用：就是指在程序代码中普遍存在的，类似 `Object obj = new Object()`这类的引用，只要强引用还在，垃圾收集器永远也不会回收掉被引用的对象。
        2、软引用：一些还有用，但又不是必须的对象，针对软引用，在系统将要发生聂村溢出异常之前，将会把这些对象放入回收范围之内并进行第二次回收。
        3、弱引用：强度比软引用还弱一些，被弱引用关联的对象只会存活到下一次垃圾收集之前，当下一次垃圾收集进行时，无论内存是否足够，弱引用关联的对象都会被回收。
        4、虚引用：幽灵引用或者幻影引用，是最弱的一种引用，虚引用是否存在不会对对象的存货时间有任何影响，当然，也无法通过虚引用拿到一个对象实例。虚引用的唯一目的就是希望在这个对象被回收时收到的一个系统通知。

        在根搜索算法中，有些对象对 GC Roots节点对象来说是不可达的，那么这些对象是会在下一次GC的时候直接回收吗？其实不然，在根搜索完成后，GC只是标记这些对象是可被回收的，并不是真正在下一次GC的时候被回收。那么这些对象是什么情况下被回收呢？只有在一个对象经历两次标记的过程，GC才会回收这个对象。
        两次标记的具体过程：如果一个对象在根搜索后发现没有与GC Roots 相连接的引用链，那么这个对象就会经历一次标记并且进行筛选，筛选的条件是该对象是否有必要执行 finalize() 方法。而判断是否有必要执行 finalize()方法的条件就是：对象有覆盖 finalize()并且finalize()方法没有被虚拟机调用过。一旦判断这个对象有必要执行 finalize() 方法，那么这个对象将会放在一个名为 F-Queue的队列中，并且之后有一条有虚拟机建立，优先级低的Finalizer线程去执行。这个线程执行这个方法的方式仅仅只是值虚拟机会触发这个方法，但是并不等待方法执行结束。而虚拟机这样做的原因就是担心某个对象的finalize()方法执行缓慢，或者直接死循环了，这样的话将会导致 F-Queue队列中其他对象永久处于等待状态，得不到执行。严重的话，会导致内存回收系统挂掉。finalize()方法是对象避免被回收的最后一次机会，因为GC稍后会对F-Queue中的对象进行第二次小规模的标记。如果在第二次标记之前，对象与GC Roots任一引用链上的对象建立关联，那么这个对象在第二次标记时会被移出即将回收的对象的集合。

### 三、方法区的回收

        方法区的垃圾回收的效率比较低。方法区的垃圾收集主要是回收两部分内容：废弃常量和无用的类。
#### 3.1 废弃常量的回收
        废弃常量的回收与Java堆中的对象回收非常类似。以常量池中的字面量回收为例，假如一个字符串"abc"已经进入常量池中，但是当前系统没有一个String对象是叫做"abc"的，换计划说没有任何String对象引用常量池中的"abc"常量，也没有其他地方引用了这个字面量，如果在这时候发生了内存回收，而且必要的话，这个"abc"常量就会被系统清除出常量池。常量池中的其他类、方法、字段的符号引用也与此类似。

#### 3.2 无用的类的回收：
        要判断一个类是无用的类，条件是比较苛刻的，这个类必须满足以下3个条件：
        1、该类所有的实例都已经被回收
        2、加载该类的ClassLoader已经被回收；
        3、该类对应的java.lang.class对象没有在任何地方被引用，无法再任何地方通过反射访问该类的方法。
        针对满足以上3个条件的类，虚拟机可以对这些类进行回收，但不是一定会回收。Hotspot虚拟机提供了一个 -Xnoclassgc 参数可以控制这些无用类的回收。还可以使用-verbose:class 和 -XX:+TraceCLassLoading、-XX:+TraceClassUnLoading参数查询类的加载接卸载信息。
