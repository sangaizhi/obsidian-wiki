## 一、volatile 和 synchronized 关键字

Java 是支持多个线程同时访问同一个对象或者对象的成员变量，而且每个线程都可以拥有这个变量的一份拷贝（虽然对象及其成员变量分配的内存是在共享内存中，但是为了加速程序的执行，每一个线程还是可以拥有一份拷贝），所以在程序的执行过程中，一个线程看到这个变量的值不一定是最新的。如何让任何一个线程看到这个变量的值都是最新的呢？

### 1.1、volatile 关键字

**volatile**关键字是用来修饰成员变量的，任何线程对**volatile**成员变量的访问都将是从共享内存中获取；对**volatile**成员变量的修改都必须刷新回共享内存。所以 **volatile** 可以保证变量对所有线程的访问可见性。

### 1.2、synchronized 关键字

**synchronized **关键字可以用来修饰方法、代码块，通过修饰方法或者同步块的方式来保证多个线程在同一时刻只会有一个线程在执行方法或者代码块，从而保证线程对共享变量访问的可见性和排他性。



## 二、等待/通知机制

**等待/通知机制**：是指在多线程环境中，一个线程A调用了对象O的`wait()`方法进入了等待状态，另一个线程B调用了对象O的`notify()`或`notifyAll()`方法，线程A收到通知后从对象O的`wait()`返回，进而继续执行。

**等待/通知机制**的相关方式是在`Object`类中的，也就是说任意的Java对象都具有**等待/通知**的能力。

相关方法：

| 方法名称       | 描述                                                         |
| -------------- | ------------------------------------------------------------ |
| notify()       | 通知一个正在该对象上等待的线程，使其从`wait()`方法返回,但是返回的前提是这个线程获得该对象的锁 |
| notifyAll()    | 通知所有等待在该对象上的线程                                 |
| wait()         | 调用该方法的线程进入 **WAITING** 状态，只有等待另外线程的通知或者中断才会返回。注意：调用`wait()`方法回释放对象的锁 |
| wait(long)     | 超时等待一段时间，这里的时间参数单位是毫秒，如果等待超过这个时间，该线程就会返回。 |
| wait(long,int) | 对于超时时间更细粒度的而控制，可以达到毫秒                   |

* 线程调用对象O的 `wait()`、`notify()`、`notifyAll()`是需要先对对象O加锁

* 线程调用对象O的 `wait()`方法后，该线程的状态就会从 `RUNNING`变成`WAITING`，并把该线程放到该对象O的等待队列中。
* 一个线程调用对象O的`notify()`、`notifyAll()`方法后，等待在该对象O上的线程并不会立即从`wait()`方法返回，而是需要等到调用

`notify()`、`notifyAll()`的线程释放对象锁后，等待的线程才有机会从 `wait()`返回。

* `notify()`、`notifyAll()` 方法都是将等待队列中的等待线程移到同步队列中，区别在于`notify()`方法只会将一个等待线程移动同步队列，而`notifyAll()`方法是将等待队列中的所有线程都移到同步队列中。被移动的线程的状态由 `WAITING`状态转变为`BLOCKED`状态。至于为什么不是 `RUNNING`状态，是因为线程还需要竞争到对象锁才能被CPU调度执行。
* 线程从 `wait()`方法返回（从 `WAITING`状态转变为`BLOCKED`状态不是返回）的前提是获得了对象的锁。



## 三、Thread.join()

`Thread.join()`方法的含义是：当前执行该行代码的线程需要等待 thread线程终止之后才从 `thread.join()`返回。同样`thread.join()`也具有超时特性的方法：`thread.join(long millis)`和`thread.join(long millis,int nanos)`。

示例代码：

```java
public class ThreadJoinDemo {

    public static void main(String[] args) {
        Thread pre = Thread.currentThread();
        for (int i = 0; i < 5; i++) {
            Thread thread = new Thread(new JoinThread(pre),"join-thread-"+i);
            thread.start();
            pre = thread;
        }
        SleepUtils.second(5);
        System.out.println(Thread.currentThread().getName()+" terminate");
    }

    static class JoinThread implements Runnable{
        private Thread thread;
        public JoinThread(Thread thread){
            this.thread = thread;
        }
        @Override
        public void run() {
            try {
                thread.join();
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
            System.out.println(Thread.currentThread().getName()+" terminate");
        }
    }
}
// 输出结果
main terminate
join-thread-0 terminate
join-thread-1 terminate
join-thread-2 terminate
join-thread-3 terminate
join-thread-4 terminate
```

从上述代码输出结果来看，每一个线程都需要等待前面一个线程终止后才从`join()`返回。
