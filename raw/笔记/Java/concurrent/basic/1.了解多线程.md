## 一、并发与并行
* 并发：两个或多个事件在同一时间间隔内发生。    
从微观上讲，以线程为例，CPU通过不断分配时间片的方式切换线程，让两个或多个线程在同一时间间隔内都被运行。    
从宏观上讲，已请求为例，服务在指定时间单位内能够处理两个或多个请求，这个请求的数量就称之为并发了。
* 并行：两个或多个事件在同一时刻发生。

**影响并发的因素：**    
硬件：内存、磁盘、CPU、网络    
软件：线程数量、JVM内存分配大小、网络通信机制（BIO、NIO、AIO）、磁盘IO

## 二、什么是线程
线程是现代操作系统调度的最小单元，也叫做轻量级进程。在一个进程里面可以创建多个线程，这些线程都有各自的计数器、堆栈和局部变量等属性，并且能够访问共享的内存变量。处理通过高速切换这些线程，让用户感觉这些线程在同时执行。

## 三、为什么使用多线程
1. 现代机器更多的处理器核心    
   现代处理器的核心数量越来越多，以及超线程技术的广泛应用；如何使用好这些处理器的多个核心也就成了现在的主要问题。而线程作为操作系统调度的基本单元，一个线程在同一时刻只能运行在一个核心上。所以，正确的使用多线程能够显著减少程序的执行时间。
2. 更快的响应时间    
   针对复杂的业务场景，其中某些操作对数据一致性的要求不强，我们就可以使用多线程把这些操作分派到不同的处理核心上执行，缩短相应时间，提升了用户体验。


## 四、线程的优先级
   现代操作系统采用时间分片的方式运行线程，所以就存在线程竞争处理器时间片的情况。线程能够分到的时间片的多少就决定了其使用处理器资源的多少，而线程的优先级就是决定线程需要更多或更少分配处理器资源的线程属性。

   在Java中，通过线程的成员变量 `priority` 来设置优先级，该变量的取值范围为 `1~10`,默认值为`5`，优先级越高的线程分配时间片的数量可能就多于优先级低的线程。为什么是可能？ 因为在不同的JVM及操作系统上，线程的规划不尽相同，有些操作系统甚至会忽略线程优先级的设定。    

   在设置线程优先级时，针对频繁阻塞（IO操作等）的线程要设置更高的优先级，而偏重计算（需要较多的CPU时间）的线程则设置较低的优先级，确保CPU不会被偏重计算的线程独占。


## 五、线程的状态
   Java 线程在运行的生命周期中可能处于以下表格中的6中不同的状态，在某个时刻，线程只能处于其中的一个状态。    

|   状态名称   |    说明  |
|  ---------- | -------- |
|     NEW     | 初始状态，线程被构建，但是还是没有调用 start() 方法     |      |
|   RUNNABLE  | 运行状态，Java线程将操作系统中的就绪和运行两种状态笼统称为“运行中”     |
|   BLOCKED   | 阻塞状态，表示线程阻塞于锁     |
|   WAITING   | 等待状态，表示线程进入等待状态，进入该状态表示当前线程需要等待其他线程做出一些特定的动作（通知或中断）|
| TIME_WAITING| 超时等待状态，该状态不同于WAITING，它是可以在指定的时间自行返回的|
| TERMINATED  | 终止状态，表示当前线程已经执行完毕|

## 六、启动和终止线程
### 6.1、构线程
在Java中构造线程的方式：
* 实现 `Runnable` 接口并重写 `run()` 方法
* 继承 `Thread` 类并覆盖 `run()` 方法
* 实现 `Callable` 接口并结合 `FutureTask` 使用
* 通过线程池启动多线程
  * `FixedThreadPool(int n)` 固定线程池大小的线程池
  * `SingleThreadPoolExecutor` 单个线程的线程池
  * `CachedThreadPool` 不需要指定线程数量，取决于线程任务的多少，不够就创建线程，够用则回收。
  * `ScheduledThreadPool` 可延迟的定期周期性的线程


```java
import java.util.concurrent.*;    
public class BuildThread {
    
    public static class BuildByRunnable implements Runnable {
        @Override
        public void run() { }
    }

    public static class BuildByThead extends Thread {
        @Override
        public void run() { super.run(); }
    }

    public static class BuildByCallable implements Callable {
        @Override
        public String call() { return "BuildByCallable"; }
    }
    public static void main(String[] args) {

        // 实现 Runnable 接口
        BuildByRunnable runnable = new BuildByRunnable();
        new Thread(runnable).start();

        // 实现 Callable 接口并且具有返回值
        new Thread(new FutureTask<>(new BuildByCallable())).start();
        
        // 继承 Thread 类
        new BuildByThead().start();

        // 线程池
        // 固定线程数量的线程池
        Executors.newFixedThreadPool(5);
        // 单个线程的线程池
        Executors.newSingleThreadExecutor();
        // 缓存线程池
        Executors.newCachedThreadPool();
        // 可延迟的定期执行的线程池
        Executors.newScheduledThreadPool(10);
    }   
}

```
### 6.2、启动线程

​        当一个线程对象在初始化完成之后，通过调用这个线程对象的 `start()` 方法就可以启动这个线程了。调用 `start()` 的含义是：当前线程同步通知虚拟机，只要线程规划器空闲，就立即启动调用`start()`的线程。

```java
new Thread(() -> System.out.println("run...")).start();
```



### 6.3、终止线程

#### 6.3.1、线程中断

​         在了解如何终止线程之前，需要先了解一下**线程中断**这个概念。

​         中断可以理解为线程的一个标识位属性，表示一个**运行中**的线程是否被其他线程进行了中断操作。中断操作就像是其他的线程对正在运行的线程打了个招呼，其他线程通过调用目标线程的 `interrupt()`方法对其进行中断。需要注意的是，线程被其他线程中断并不意味这个线程立即退出运行。

​        一个线程可以通过 `isInterrupted()`方法来判断自己是否被其他线程中断，从而进行中断响应。当然也可以通过 `Thread.interrputed()` 方法对当期线程的中断标识位进行复位。

**注意：**通过`isInterrupted()`方法判断线程是否被中断过，只能判断还未终结的线程；针对终结的线程，即时被中断过，这个方法也会返回 `false`。

​       对于 Java API 中的 `InterruptedException`异常，在抛出该异常之前，虚拟机会把这个线程的中断标识位进行清除，然后再抛出`InterruptedException `异常。所以在抛出异常之后再调用 `isInterrupted()` 方法得到的结果将会是`false`。

**代码示例：**

```java

public class InterruptedDemo {
    public static void main(String[] args) {
        Thread sleepThread = new Thread(new SleepRunner(),"sleep-thread");
        sleepThread.setDaemon(true);
        Thread busyThread = new Thread(new BusyRunner(),"busy-thread");
        sleepThread.setDaemon(true);

        sleepThread.start();
        busyThread.start();

        SleepUtils.second(5);

        sleepThread.interrupt();
        busyThread.interrupt();

        System.out.println("SleepThread interrupted is:"+ sleepThread.isInterrupted());
        System.out.println("BUsyThread interrupted is:"+ busyThread.isInterrupted());

        SleepUtils.second(2);
    }

    static class SleepRunner implements Runnable{
        @Override
        public void run() {
            while (true){
                try{
                    TimeUnit.SECONDS.sleep(10);
                }catch (InterruptedException e){
                }
            }
        }
    }
    static class BusyRunner implements Runnable{
        @Override
        public void run() {
            while (true){
            }
        }
    }
}
//  输出的结果
SleepThread interrupted is:false
BUsyThread interrupted is:true
```

​      从上面代码中可以看出，抛出了 `InterruptedException`异常的线程SleepThread，其中断标识位被清除了，而BusyThread没有被清除。

#### 6.3.2、线程的暂停、恢复和终止

​      在Java 的 API 中，存在着一组**过期**的针对线程操作的API：`suspend()`、`resume()`、`stop()`。这三个API实现一个线程的暂停、恢复和终止。这些 API 看似

见名知意、很好理解，但是这些 API 是**过期**的，不推荐使用的。而不推荐使用的原因是因为这些 API 仅仅只是实现了对线程的操作，但是没有关注其他资源。比如

`suspend()` 方法，调用这个方法，线程确实会被暂停，但是是占着资源的方式进入睡眠状态，这样就很容易引发死锁问题了。又或者说 `stop()`方法，这个方法在结束一个线程时并不会保证线程占有的资源会被释放（一般是没有给线程完成释放资源的机会），这样就会导致一些不确定的问题。

#### 6.3.3、如何安全的终止一个线程

​    在前面提到，线程有一个中断状态标识位，而中断操作就是线程之间一种简单的交互方式。通过中断操作，我们可以很简单的取消或者停止任务。

**示例代码：** 

```java

public class StopThreadDemo {
    public static void main(String[] args) throws InterruptedException {
        Runner one = new Runner();
        Thread countThread = new Thread(one, "CountThreadOne");
        countThread.start();
        TimeUnit.MILLISECONDS.sleep(500);
        // 通过中断终止线程
        countThread.interrupt();

        Runner two =new Runner();
        countThread = new Thread(two,"CountThreadTwo");
        countThread.start();
        TimeUnit.MILLISECONDS.sleep(500);
        // 通过变量终止任务
        two.cancel();
    }
    
    private static class Runner implements Runnable {
        private long i = 0L;
        private volatile boolean on = true;

        @Override
        public void run() {
            while (on && !Thread.currentThread().isInterrupted()) {
                i++;
            }
            System.out.println(Thread.currentThread().getName()+" count i:" + i);
        }
        public void cancel() {
            on = false;
        }
    }
}
// 输出结果
CountThreadOne count i:412957118
CountThreadTwo count i:425844864
```

​      在上面的代码中，通过中断线程和调用 `cancel()` 方法都可以使线程终止，这种方式让线程在终止时有机会去释放资源，而不是简单的将线程停止，因此这种终止线程的方式显得更加安全。
