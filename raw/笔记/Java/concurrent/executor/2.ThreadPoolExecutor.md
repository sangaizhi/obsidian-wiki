## ThreadPoolExecutor

`ThreadPoolExecutor` 是`Executor` 框架最核心的类，是线程池的实现类。

主要有一下几个组件组成：

* corePoolSize : 核心线程池的大小
* maximumPoolSize: 最大线程池的大小
* workQueue:  用来暂时保存任务的工作队列
* RejectedExecutionHandler： 当 `ThreadPoolExecutor`已经关闭或者ThreadPoolExecutor已经饱和时，execute() 方法将要调用的 Handler。

通过 `Executors`工具类，我们可以创建以下三种类型的 `ThreadPoolExecutor`:

### 1. FixedThreadPool

由`Executors`提供，创建使可重用固定线程数的线程池，其 `corePoolSize`和`maximumPoolSize` 都被设置成创建线程池时指定的参数`nThreads`。`API`如下：

```java
/**
 * 创建固定数量线程的线程池，使用共享无界队列存储等待的任务
 */
public static ExecutorService newFixedThreadPool(int nThreads) {
   return new ThreadPoolExecutor(nThreads, nThreads, 0L, TimeUnit.MILLISECONDS, new LinkedBlockingQueue<Runnable>());
}
/**
 * 创建固定数量线程的线程池,其中线程的创建采用指定的线程池
 */
public static ExecutorService newFixedThreadPool(int nThreads, ThreadFactory threadFactory) {
   return new ThreadPoolExecutor(nThreads, nThreads, 0L, TimeUnit.MILLISECONDS, 
                                 new LinkedBlockingQueue<Runnable>(), threadFactory);
}
```

该线程池的特点：

* 线程数量固定；
* 当所有的线程都处于活动的状态时，此时提交的任务将会放在等待队列；
* 如果线程在执行过程中因异常而终止，如果后续需要，将会换一个新的线程来执行后续任务。
* 由于`FixedThreadPool`使用无界队列（队列的容量为`Integer.MAX_VALUE`）作为线程池的工作队列，所以存在以下特点：
  * 当线程池的线程数达到 `corePoolSize`之后，新提交的任务将放在无界队列中等待，所以线程池中的线程数不会超过`corePoolSize`。
  * `maximumPoolSize`参数无效，因为当线程池的线程数达到 `corePoolSize`之后，不会在创建新的线程；
  * `keepAliveTime`参数无效，因为没有超出`corePoolSize`大小的线程；
  * 运行中的 `FixedThreadPool` （未执行`shutdown()`或者 `shutdownNow()`）不会拒绝任务，也就是不会调用 `RejectedExecutionHandler.rejectedExecution()`方法。

##### `FixedThreadPool`执行`execute()`方法的运行流程图：

![](https://blog-1253360328.cos.ap-guangzhou.myqcloud.com/assets/java/concurrent/executor/FixedThreadPool_execute.png)

1. 主线程执行 `execute()` 方法提交一个任务到线程池，如果线程池中有空闲的核心线程，则直接由空闲线程执行任务；
2. 如果线程池中没有空闲的核心线程，则把任务添加到`LinkedBlockingQueue`等待队列中；
3. 当核心线程执行完一个任务后，会去`LinkedBlockingQueue`队列的队头拿一个任务执行。

**`FixedThreadPool` 适用于为了满足资源管理，而需要限制当前线程数量的应用场景，适用于负载较重的服务器。**

### 2. CachedThreadPool

由`Executors`提供，创建一个根据使用需要而创建线程的线程池。`API`如下：

```java
/**
 * 创建一个线程池，这个线程池中线程的创建是根据需要的时候创建的
 */
public static ExecutorService newCachedThreadPool() {
    return new ThreadPoolExecutor(0, Integer.MAX_VALUE, 60L, TimeUnit.SECONDS, new SynchronousQueue<Runnable>());
}

/**
 * 和上一个方法一样，区别就是使用指定的线程工厂创建线程
 */
public static ExecutorService newCachedThreadPool(ThreadFactory threadFactory) {
    return new ThreadPoolExecutor(0, Integer.MAX_VALUE, 60L, TimeUnit.SECONDS, new SynchronousQueue<Runnable>(), threadFactory);
}
```

​	在创建`CachedThreadPool`线程时，线程池的`corePoolSize`被设置成`0`，`maximumPoolSize`被设置成 `Integer.MAX_VALUE`， `keepAliveTime`被设置成`60`秒。使用没有容量的`SynchronousQueue`阻塞队列作为任务的等待队列。从参数上可以看出，该线程池的特点：

* 线程池的最大线程数是 `Integer.MAX_VALUE`,可以认为是大小无界的线程池。**当提交任务的速度高于 `maximumPool` 中处理任务的速度时，线程池会不断创建新的线程，从而耗尽`CPU`和内存资源**。

* 根据是否需要进行线程的创建；
* 线程可复用，当线程池的线程可用时，新提交的任务可复用之前创建的线程（线程在销毁之前会在``SynchronousQueue``等待`60`秒）；
* 60秒未使用的线程将会被销毁并从线程池中移出，因此这个线程池的空闲的时间很长也不会消耗资源（因为没有线程）；

##### `SynchronousQueue`阻塞队列的特点：

* 没有容量
* 每个插入操作必须等待另一个线程的对应移除操作。

##### 该线程池的`execute()` 方法运行流程图：

![CachedThreadPool.Execute](https://blog-1253360328.cos.ap-guangzhou.myqcloud.com/assets/java/concurrent/executor/CachedThreadPool_execute.png)

1. 主线程线程池在调用 `execute()`之后，首先执行`SynchronousQueue.offer(Runnable task)`，如果当前线程池的 `maximumPool`为空，或者说`maximumPool`中没有空闲线程时，将没有线程执行`SynchronousQueue.poll(keepALiveTime, TimeUnit.NANSECONDS)`，此种情况下，`CachedThreadPool`会创建一个新线城执行任务，`execute()`方法执行完成。 
2. 如果当前的 `maximumPool`中有空闲线程正在执行`SynchronousQueue.poll(keepALiveTime, TimeUnit.NANSECONDS)`，那么主线程执行的`offer`操作与空闲线程执行的`poll`操作配对成功，此时，主线程就会把任务交给空闲线程执行。
3. 在步骤1中新创建的线程在任务执行完成后，会执行`SynchronousQueue.poll(keepALiveTime, TimeUnit.NANSECONDS)`。这个操作会让空闲线程在`SynchronousQueue`等待`60`秒。如果在这`60`秒内提交了一个新任务，那么这个空闲线程将执行新提交的任务；否在超过`60`秒，该空闲线程将被终止。

**注意**：`SynchronousQueue` 是一个没有容量的阻塞队列，所以它不会存放任何待执行的任务。也就是说，主线程提交一个任务给 `CachedThreadPool`,就必须等待`CachedThreadPool`线程池有空闲线程在 `SynchronousQueue` 上执行｀poll｀操作。如果线程池没有空闲线程，就会创建一个线程去`SynchronousQueue` 上执行`poll`操作，然后和主线程匹配；如果有空闲线程在`poll`操作，则匹配主线程和空闲线程，然后把任务给到这个空闲线程执行。

**`CachedThreadPool`适用于适用于执行执行周期短的任务或者负载很轻的服务器。**

### 3. SingleThreadExecutor

由`Executors`提供，与`FixedThreadPool`的大部分属性一致，仅仅是把`corePoolSize`和`maximumPoolSize`都设置成1，所以`SingleThreadExecutor`是一个只有一个线程的线程池。`API`如下：

```java
/**
 * 创建一个只有一个线程的线程池，该线程池使用无界队列存储等待的任务
 */
public static ExecutorService newSingleThreadExecutor() {
    return new FinalizableDelegatedExecutorService (
        new ThreadPoolExecutor(1, 1, 0L, TimeUnit.MILLISECONDS, new LinkedBlockingQueue<Runnable>()));
}

/**
 * 和上一个方法一样，区别就是使用指定的线程工厂创建线程
 */
public static ExecutorService newSingleThreadExecutor(ThreadFactory threadFactory) {
    return new FinalizableDelegatedExecutorService
        (new ThreadPoolExecutor(1, 1, 0L, TimeUnit.MILLISECONDS, new LinkedBlockingQueue<Runnable>(),threadFactory));
}
```

该线程池具有以下特点：

* 用永远只有一个线程；
* 如果当前的线程在执行过程中遇到执行失败而被终止时，一旦有下一个任务需要执行，就会创建一个新的线程来代替当前线程；
* 提交到该线程池的任务将会顺序执行，并且同一时间，该线程池的中任务有且仅有一个被执行；
* 与 `FixedThreadPool(1)`不同，返回的`Executor`可以保证其不可以重新配置来使用其他线程。

##### 该线程池的`execute()` 方法运行流程图：

![](https://blog-1253360328.cos.ap-guangzhou.myqcloud.com/assets/java/concurrent/executor/SingleThreadPool_execute.png)

1.  主线程执行 `execute()`提交一个任务，如果当前没有运行的线程数（线程数小于1,`corePoolSize`为1）,则创建一个新的线程来执行任务；
2.  如果线程池总有一个运行的线程，则将任务加入到`LinkedBlockingQueue`中；
3.  线程池中的线程执行任务后，会在一个无限循环中反复从 `LinkedBlockingQueue`中获取任务来执行。

**`SingleThreadExecutor`适用于需要保证顺序执行任务，并且在任意时间，不会有多个活动线程的场景**
