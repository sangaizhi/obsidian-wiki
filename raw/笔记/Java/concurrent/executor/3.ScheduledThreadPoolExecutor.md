

## ScheduledThreadPoolExecutor

### 1. ScheduledThreadPoolExecutor 简介

`ScheduledThreadPoolExecutor` 其实也是继承于`ThreadPoolExecutor`,但相对于前面提到的`FixedThreadPool`、`SingleThreadPool`和`CachedThreadPool`，它具有延迟执行任务或者定期执行任务的功能。其构造方法如下：

```java
/**
 * 使用给定的核心线程数创建一个线程池，其等待队列使用的是 DelayedWorkQueue
 */
public ScheduledThreadPoolExecutor(int corePoolSize) {
    super(corePoolSize, Integer.MAX_VALUE, 0, NANOSECONDS, new DelayedWorkQueue());
}
/**
 * 使用给定的核心线程数和线程工厂创建一个线程池
 */
public ScheduledThreadPoolExecutor(int corePoolSize, ThreadFactory threadFactory) {
    super(corePoolSize, Integer.MAX_VALUE, 0, NANOSECONDS, new DelayedWorkQueue(), threadFactory);
}
/**
 * 使用给定的核心线程数和拒绝策略创建一个线程池
 */
public ScheduledThreadPoolExecutor(int corePoolSize, RejectedExecutionHandler handler) {
    super(corePoolSize, Integer.MAX_VALUE, 0, NANOSECONDS, new DelayedWorkQueue(), handler);
}
/**
 * 上面三个构造方法的合并
 */
public ScheduledThreadPoolExecutor(int corePoolSize, ThreadFactory threadFactory, RejectedExecutionHandler handler) {
    super(corePoolSize, Integer.MAX_VALUE, 0, NANOSECONDS, new DelayedWorkQueue(), threadFactory, handler);
}
```

从构造方法看，`ScheduledThreadPoolExecutor` 仅能指定核心线程数，其最大线程数设置为`Integer.MAX_VALUE`。其实在 `ScheduledThreadPoolExecutor` 线程池中 `maximumPoolSize` 参数是没有意义的，因为其采用的的等待队列`DelayedWorkQueue`是一个无界队列，意味着这个队列永远也不会塞满，永远不会创建除核心线程之外的线程。

### 2. ScheduledThreadPoolExecutor 的运行机制

`ScheduledThreadPoolExecutor `的运行机制主要是两个部分：

* 调用 `schedule()` 或者 `scheduleAtFixedRate()`或者 `scheduleWithFixedDelay()`方法时会向 `DelayedWorkQueue`添加一个实现了 `RunnableScheduledFuture`接口的 `ScheduledFutureTask`。
* 线程池中的线程从`DelayedWorkQueue` 中获取 `ScheduledFutureTask`，然后执行Task。

### 3. ScheduledThreadPoolExecutor 的主要成员

*  DelayedWorkQueue

  一个 `ScheduledThreadPoolExecutor `线程池专用的延时队列，是一个 `BlockingQueue`的实现，只能用来装载可执行的任务。

`DelayedWorkQueue`是一个基于堆的数据结构实现的, 其中存放的不只是每个 `ScheduledFutureTask`，还将**`ScheduledFutureTask`的索引记录到堆数组中**。所以在删除任务的时候，就不需要进行大量的遍历搜索，只需要根据任务的索引找到对应的任务，大大提高了删除速度。另外，这个索引记录还能够减少垃圾堆积，因为不需要把任务上升的数组的顶部（rise to top）以达到清除的目的，而只需要把删除的数据的索引改为 `-1`，然后重新构造堆结构（堆化）。具体介绍可以参考 [DelayedWorkQueue介绍]("../java/concurrent/executor/5.ScheduledThreadPoolExecutor_DelayedWorkQueue.md")

* `ScheduledFuture`

  一个Future的定义，它定义的是一个被取消的任务的结果，通常这个结果是通过`ScheduledExecutorService`调度的任务产生。

* `RunnableFuture`

  也是一个 `Future` 的定义，它定一个是一个可以执行的 `Future`，一旦该`Future`的`run()`方法的执行成功，就意味这个 `Future` 的完成，然后就可以访问它的结果了。

* `ScheduledFutureTask`

  ScheduledFutureTask 是`RunnableScheduledFuture`的实现，它就是 `ScheduledThreadPoolExecutor `线程池中任务的具体表现。主要属性及功能参考 [ScheduledFutureTask介绍](../java/concurrent/executor/6.ScheduledThreadPoolExecutor_ScheduledFutureTask.md)

* `RunnableScheduledFuture`

  这是一个更加具体 `ScheduledFuture` 定义，它结合了 `RunnableFuture` 的含义，并且增加了一个表明该任务是否是一个周期性的任务的方法(isPeriodic()`)。

* `RunnableScheduledFuture`

```java
public ScheduledFuture<?> scheduleAtFixedRate(Runnable command, long initialDelay, long period, TimeUnit unit) {
    if (command == null || unit == null) { throw new NullPointerException(); }
    if (period <= 0) { throw new IllegalArgumentException(); }
	// 把要执行的任务包装成一个
    ScheduledFutureTask<Void> sft = new ScheduledFutureTask<Void>(command, null, 
                                                                  triggerTime(initialDelay, unit), unit.toNanos(period));
    RunnableScheduledFuture<Void> t = decorateTask(command, sft);
    sft.outerTask = t;
    delayedExecute(t);
    return t;
}
public ScheduledFuture<?> scheduleWithFixedDelay(Runnable command, long initialDelay, long delay, TimeUnit unit) {
    if (command == null || unit == null) { throw new NullPointerException();}
    if (delay <= 0) { throw new IllegalArgumentException(); }

    ScheduledFutureTask<Void> sft =
        new ScheduledFutureTask<Void>(command,null, triggerTime(initialDelay, unit), unit.toNanos(-delay));
    RunnableScheduledFuture<Void> t = decorateTask(command, sft);
    sft.outerTask = t;
    delayedExecute(t);
    return t;
}
private void delayedExecute(RunnableScheduledFuture<?> task) {
    if (isShutdown()) {
         reject(task);
    }else {
        super.getQueue().add(task);
        if (isShutdown() && !canRunInCurrentRunState(task.isPeriodic()) &&remove(task)){
             task.cancel(false);
        } else{
            ensurePrestart();
        }   
    }
}
```
