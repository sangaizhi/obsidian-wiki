##  一、为什么使用线程池

池化技术已经我们常用的一种技术，例如线程池、数据库连接池等都使用了池化技术。池化技术的主要思想就是通过复用减少资源的消耗，提升资源的使用率。

线城池也是池化技术具体应用，通过预先创建好若干线程的方式，避免了线程的频繁创建和回收，节省了系统资源开销。

线程池的好处：

* 降低资源消耗。通过复用已经创建好的线程避免创建和销毁线程的资源消耗；
* 提升响应速度。当一个任务需要执行时，不需要去重新创建线程，而是使用已有的线程，节省了创建线程的时间。
* 提高线程的可管理型。使用线程池可以对线程进行同一的管理，并且方便监控调优。



## 二、线程池的实现原理

当一个任务被提交到线程池后，线程池执行该任务的基本流程就是：

1.  判断线程池中的核心线程是否都在执行任务。如过不是，则创建一个新的工作线程来执行任务；如果核心线程池中的线程都在执行任务，则进入下一个流程。
2.  判断线程池的工作队列是否已满。如果工作队列没有满，则将这个任务加入到工作队列中；如果工作队列已满，则进入下一个流程。
3.  判断线程池的线程是否都处于工作状态。如果没有，则创建一个新的工作线程来执行任务；如果都处于工作状态，则交给饱和策略来处理这个任务。

## 三、线程池的使用

### 3.1、线程池的创建

`new ThreadPoolExecutor(int corePoolSize, int maximumPoolSize, long keepAliveTime, TimeUnit unit, BlockingQueue<Runnable> workQueue,ThreadFactory threadFactory, RejectedExecutionHandler handler)`

* `corePoolSize`

  线程池的基本大小，当提交一个任务，如果线程池中的核心线程数小于该参数值，则会创建一个新的线程来处理该任务，即使其他的核心线程是空闲状态。等到需要执行的任务数大于线程池核心大小时就不再创建核心线程数。如果调用了线程池的 `preStartAllCoreThreads()`方法，线程池就会提前把所有的核心线程都创建好。

* `maximumPoolSize`

  线程池允许创建的最大线程数量。如果任务队列满了，并且已创建的线程数小于最大线程数，则会创建新的线程执行任务。需要注意的是，如果使用了无界队列，这个参数就没有什么效果。

* `keppAliveTime`

  线程活动保持时间，当线程池的工作线程空闲后，保持存活的时间。所以针对任务很多并且单个任务的执行时间非常短的线程池，可以调大该时间参数，提升线程的利用率。

* `TimeUnit`

  线程活动保持时间的单位。有天、小时、分钟、毫秒、微秒、纳秒

* `workQueue`

  任务队列，用来保存等待执行的任务的阻塞队列，有以下几个可以选择：

  * `ArrayBlockingQueue` : 基于数组结构的有界阻塞队列，按照`FIFO`对元素进行排序。
  * `LinkedBlockingQueue` :基于链表结构的阻塞队列，按照`FIFO`对元素排序，吞吐量通常高于``ArrayBlockingQueue` 。`Executors.newFixedThreadPool()` 使用的就是这个队列。
  * `SynchronousQueue` ：不存储元素的队列。每个插入操作必须等待另一个线程调用移除操作，否则插入操作就一直处于阻塞状态。吞吐量通常高于`LinkedBlockingQueue` 。`Executors.newCachedThreadPool()` 使用的就是这个队列。
  * `PriorityBlockingQueue` : 具有优先级的无解阻塞队列。

* `ThreadFactory`

  用于设置线程的工厂，通过这个工厂可以给线程设置名称。

* `RejectedExecutionHandler`

  饱和策略。当队列和线程池都满了，线程池已经处于饱和状态，就必须采取一种策略来处理新提交的任务。默认策略是 `AbortPolicy`，表示无法处理新的任务时抛出异常。有4中策略可选：

  * `AbortPolicy` : 直接抛出异常；
  * `CallerRunsPolicy` : 使用调用者所在的线程来执行任务；
  * `DiscardOldestPolicy` : 丢弃队列里最近的一个任务，并执行当前任务；
  * `DiscardPolicy` : 不处理，直接丢掉。



### 3.2、提交任务

通过 `execute(Runnable runnable)` 或者 `submit()` 方线程池提交任务。

* `execute()` 方法用于提交不需要返回值任务，所以无法判断任务是否被线程池执行成功。`execute()`接收的是一个 `Runnable` 实例。
* `submit()` 方法用于向线程池提交需要返回值的任务。线程池会返回一个 `future`类型的对象。通过这个 `future`对象可以判断任务是否执行成功，通过 `future` 的 `get()` 方法获取返回值。需要注意的是`get()`方法会阻塞当前线程知道任务完成，当然也可以使用`get(long timeout, TimeUnit unit)`方法指定阻塞的时间， 这时候有可能任务没有执行完。

```java
public class ThreadPoolDemo {

    public static void main(String[] args) throws ExecutionException, InterruptedException {
        // 创建线程池
        ThreadPoolExecutor executor = new ThreadPoolExecutor(10,20,1000, TimeUnit.MILLISECONDS, new LinkedBlockingQueue<Runnable>());
        executor.execute(() -> System.out.println("execute runnable"));
       Future<String> future = executor.submit(() -> {
           System.out.println("submit callable");
           return "success";
       });
       String result = future.get();
       System.out.println("result:"+result);
    }
}

```

------

`ThreadPoolExecutor` 执行 `execute()` 方法主分为四种情况：

* 如果线程池中当前运行的线程少于 `corePoolSize`, 则会创建新的线程来执行提交的任务。注意，执行这个步骤需要获取线程池的全局锁，是为了避免队列未满，但是线程池的线程数量大于核心线程数。
* 如果运行的线程等于或者对于 `corePoolSize`，则将任务加入等待队列。
* 如果无法将任务添加到等待队列(eg：队列已满的情况)，则创建新的线程来处理任务。注意，执行这一步骤也会获取线程池的全局锁，也是为了保证线程池的线程总数小于 `maximumPoolSize`。
* 如果创建新线程将会导致当前运行的线程的数量大于 `maximumPoolSize`,任务将会被拒绝，具体采用何种拒绝策略，取决去创建线程池时指定的拒绝策略。默认的拒绝策略是`AbortPolicy` （直接抛出异常）。

### 3.3、关闭线程池

关闭线程池就是通过调用线程的 `interrupt`方法来中断线程池的所有线程，所以无法响应中断的任务可能就永远无法终止。可以通过 `shutdown()` 和 `shutdownNow` 方法来关闭线程池。

* `shutdown()` 将线程池的状态设置成 `SHUTDOWN` 状态，然后中断所有没有正在执行任务的线程。
* `shutdownNow()` 将线程池的状态设置为 `STOP` 状态，然后尝试停止所有的正在执行或暂停任务的线程，并返回等待执行任务的列表。

一旦 `shutdown()`或者 `shutdownNow()`方法被调用， 线程池的 `isShutdown()`方法就会返回 `true`。当所有的任务都已关闭后，才表示线程池已经成功关闭，此时调用`isTerminaed()`方法会返回 `true`。



### 3.4、配置线程池

要合理的配置线程池，必须要分析了解任务的特性。

任务的维度：

* 性质：CPU密集型、IO密集型、混合型

  **CPU密集型**任务应配置尽可能小的线程数量，如配置（CPU核心数+1）个线程的线程池。**IO密集型**的任务线程不一定一直在执行任务，有可能在等待IO，所以这种线程执行任务的时间相对较长，所以线程池的线程数可以配置多一点，例如（2倍的CPU核心数）。

* 优先级：高、中、低

  优先级不同的任务可以使用`PriorityBlockingQueue` 队里来处理。这个队列可以让优先级高的任务先执行。

  注意：如果一直有高优先级的任务提交到队列，那么队列中低优先级的任务可能永远不会执行。

* 执行时间：长、中、短

* 依赖性：是否依赖其他系统资源

建议使用**有界队列**来存储任务，能够增加系统的稳定性和预警能力，可以根据需要设置的大一点。



### 3.5、线程池监控

线程池监控可以通过以下几个属性实现：

* `taskCount`: 线程池需要执行的任务数量；
* `completedTaskCount`: 线程池在运行过程中已经完成的任务数量；
* `largestPoolSize`: 线程池曾经创建过的最大线程数量。通过这个数量可以判断线程池曾经是否满过；
* `getPoolSize`: 线程池的线程数量。如果线程池不销毁的话，线程池里的线程不会自动销毁，所有这个大小只增不减。
* `getActiveCount`: 活动的线程数
