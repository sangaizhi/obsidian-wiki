## 内容要点

### 1. 为什么需要规划与执行分离？

- **单一 Prompt 的局限：** 当 Agent 任务复杂时，把所有逻辑塞进一个 Prompt 会导致幻觉增加、可控性下降
- **解耦关注点：** Planner 负责"想清楚怎么做"，Executor 负责"脚踏实地去执行"
- **可观测性：** 分离后可以独立追踪规划是否合理、执行是否正确
- **可复用性：** 同一套规划机制可对接不同的执行工具

### 2. 典型架构分层

```
┌─────────────────────────────┐
│        用户输入(User)         │
└──────────┬──────────────────┘
           ▼
┌─────────────────────────────┐
│      Planner（规划器）        │
│  - 理解目标                   │
│  - 拆解为子任务               │
│  - 生成执行计划               │
└──────────┬──────────────────┘
           ▼  计划 (Plan: step-by-step)
┌─────────────────────────────┐
│      Executor（执行器）       │
│  - 顺序/并行执行子任务         │
│  - 调用工具/API               │
│  - 收集结果                   │
└──────────┬──────────────────┘
           ▼  中间结果
┌─────────────────────────────┐
│    Memory/反馈循环            │
│  - 存储中间状态               │
│  - 动态调整计划               │
└──────────┬──────────────────┘
           ▼
┌─────────────────────────────┐
│        最终输出(Output)       │
└─────────────────────────────┘
```

### 3. 常见实现模式

#### 模式一：ReAct（推理+行动）

Planner 和 Executor 在同一个 LLM 调用中交替完成：
- **Thought（规划）：** 当前应该做什么
- **Action（执行）：** 调用什么工具
- **Observation（反馈）：** 工具返回了什么

> 适用于：简单任务、工具调用链不长的场景

#### 模式二：Plan-and-Solve（计划+求解）

将 Planner 和 Executor 拆分为两个独立的 LLM 调用：
- **Planner：** 接收用户需求，输出完整的执行步骤列表
- **Executor：** 按 Planner 输出的步骤逐一执行，遇到失败可回传反馈

> 适用于：复杂任务、需要多步推理的场景

#### 模式三：分层 Agent（Hierarchical Agent）

- **高层 Planner（Orchestrator）：** 制定宏观计划和策略
- **中层 Coordinator：** 协调多个子 Agent
- **底层 Worker/Executor：** 具体执行原子操作

> 适用于：企业级多 Agent 协作系统

### 4. 面试重点回答方向

| 考察点 | 建议回答方向 |
|--------|-------------|
| 架构设计 | Plan → 拆分 → Execute → Feedback → Adjust 循环 |
| 工具管理 | 注册中心模式，工具 Schema 标准化 |
| 错误处理 | Executor 执行失败 → 回传 Error → Planner 重新规划 |
| 上下文管理 | 短期记忆（对话窗口）+ 长期记忆（向量数据库） |
| 性能优化 | 并行执行子任务、缓存常用规划结果 |
| 可观测性 | 日志记录每步规划与执行，支持断点续跑 |

### 5. 实际应用场景

- **代码生成 Agent：** Planner 设计架构 → Executor 逐个文件实现 → Tester 验证
- **数据分析 Agent：** Planner 制定分析计划 → Executor 执行 SQL/代码查询 → Summarizer 总结
- **自动化运维：** Planner 诊断问题 → Executor 执行修复命令 → Observer 监控效果

## 我的分析

这个视频的干货密度挺高的。**规划与执行分离** 本质上是 Computer Science 里"分治思想"在 Agent 领域的具体体现——把"决策"和"行动"拆开，是解决 Agent 可控性问题的关键一步。

实际面试中，能说出 ReAct 和 Plan-and-Solve 两种模式的差异和适用场景就已经及格了，但如果能进一步讨论 **反馈循环（Feedback Loop）** 的设计，比如 Planner 如何感知 Executor 的失败并进行动态调整，就是加分项。

另一个值得深挖的点是 **规划粒度** 问题——你不可能对所有任务都做细粒度规划（太慢），也不能全交给 Executor 随机发挥（不可控）。如何设计自适应的规划粒度，是一个非常值得思考的方向。
