# 一、工作流

- 定位：固定流水线
    
      固定的线性流程，没有决策分支，像工厂传送带一箱，步骤顺序完全固定；
    
      执行逻辑是“死”的，所有步骤都是提前预设好的，稳定性极高，绝不会出岔子；
# 二、Agent

- 定位：智能决策者
动态智能决策系统，自带“思考”能力，不再是死板的指令，而是拥有自主判断的逻辑；
会根据实时环境与反馈，灵活调整执行路径，目标导向，以最高效的方式达成最终结果。
- 适用场景：
    - 需求多变   
       Agent能自主识别真实需求，动态决定下一步的执行动作，不局限于预设的分支选项。
    - 业务逻辑复杂
       根据需求自动调用知识库查询检索有用信息，动态调整计划，完成目标任务。
    - 非结构化场景
       不受限于固定的分支流程，能够覆盖无法被预判的需求。
    

# 三、如何选择

工作流与Agent应该怎么选，什么时候用工作流，什么时候用Agent。

- 场景1：自动周报生成 -- 使用工作流
    - 数据拉取：每周固定拉取本周的业务数据
    - 图标生成：基于固定模板自动生成可视化数据图表
    - 内容填充：将数据与结论按照既定框架填入周报模板
    - 格式导出：自动导出为PDF或者图片等固定格式文件
    - 消息推送：自动发送到指定群组

     该场景的流程本身固定，无需干预，所以使用工作流即可完成，并且无需大模型，成本低，运行稳定。强行引入Agent反而增加开发调试成本，更可能阴大模型的不确定性导致流程出错。
    
- 场景2：电商客服 -- 使用Agents
    - 用户需求不确定
    
     用户咨询千奇百怪，无法预判，有人问问参数、有人退货、有人查物流，传统固定流程难以覆盖所有情况。
    
     该场景没有办法固定死所有的流程，只能靠Agent来自主决策用户的意图，基于不同用户的意图，来决定下一步的步骤。
    

**选型****黄金法则****：拒绝过度设计**

- 法则一：按需选择
    - 固定流程：工作流优先
        对于标准化、可固化的业务逻辑，坚决使用工作流引擎编排，利用其确定性强、执行稳定的特点，确保业务逻辑的精准落地；
    - 动态决策：引入Agent
        面临复杂不确定性场景时，叠加Agent智能体，利用其自主思考与工具调用特性解决动态问题。
        
- 法则二：渐进叠加
    - 基础底座：工作流先行  
	    优先搭建稳固的工作流基础，覆盖80%常规业务需求，保证系统在初期即可快速落地，并具备清晰的可维护性、可观测性；
    
    - 能力增强：渐进式叠加
        在工作流无法覆盖的长尾场景中，逐步叠加Agent能力，切忌“一步到位”的全Agent方案，避免因过度设计导致的成本高昂与系统不稳定。
        
清醒认知：非必要，不Agent，AI项目的第一性原理，拒绝盲目追求“高大上”的技术架构，实用、高效、能真正解决业务痛点，才是我们技术选型的核心标准。
