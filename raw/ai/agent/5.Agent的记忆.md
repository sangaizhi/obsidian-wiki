# 一、为什么AGI总是记不住？

原因：大模型本身没有任何记忆能力。

大模型并不具备“记忆”的生理或者逻辑基础，对大模型而言，每一次的提问于回复都是一次完全独立的、全新的计算过程，它根本无法主动“回忆”上一次对话中你提到的任何信息。

当前主流对话型AI会让我们认为“AI记住了”的错觉，核心在于系统的工程设计，在每一次交互时，程序会自动将本轮之前的所有聊天记录(上下文)打包，与当前的问题一起发给大模型，让他基于完整的上下文进行回复的生成。

# 二、大模型的短期记忆

大模型的记忆是靠聊天“凑”出来的记忆，其核心模式是将历史对话全部“投喂”给大模型，就像随身包带着笔记本，每次说话前都要快速翻一遍历史记录，以此来构建短暂的“记忆”；

**缺陷**

- 容量有限：一旦对话轮次过长，超过了大模型的“上下文窗口”上限，它就会“选择性失忆”，对前文信息丢失并开始胡编乱造。
    
- 无法持久：所有的“记忆”都依附于当前的对话窗口，一旦软件关闭，清空会话或者切换模型，所有历史上下文都会被清空，下次打开依然是“初识”状态。

# 三、解决方式

为解决短期记忆的问题，AI的长期记忆的底层逻辑：为用户建立一个“专属记忆文库”，持续记录用户的个人偏好，交互规则及关键上下文信息，每次会话启动时自动加载，每次提问时实时参考，从而实现具备“连续性”的智能交互。

其本质与短期记忆没有差别，但只不过方式更聪明，只保留关键信息。而读取这种长期记忆的核心技术，本质上就是搜索。在AI领域，这种搜索就是**RAG检索增强。**其主要逻辑不把所有的个人记忆全部喂给大模型，而是根据当前的问题，然后去记忆库里面查询对应的相关信息，再把这些相关喂给大模型，最后大模型根据这些相关信息和当前问题进行回答。

**核心优势：**避开了大模型的上下文窗口限制，防止信息过载；又能让AI基于最新、最相关的记忆，精准的记住并响应你的个性化需求。

# 四、如何构建一个记忆系统

1. 存储
将用户在对话过程中产生的关键身份信息、行为偏好以及历史对话的核心摘要进行结构化的持久保存；

2. 调用
在每次向大模型发起请求时，自动检索用户记忆信息，作为上下文内容一起发给大模型。

# 五、避坑

- 拒绝大模型的“口头承诺”
    

大模型的即时反馈往往都是临时的，所有没有落实到行动的口头保证，本质上都是不可信的敷衍；

- 唯“文件修改”为真实凭据
    

必须以“修改并保存记忆文件”为唯一标准，只有写入了文件，才意味着真正建立了长期可追溯的记忆。
