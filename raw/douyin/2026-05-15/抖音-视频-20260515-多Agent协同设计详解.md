## 视频概述

这是一个面向 AI 产品经理面试的实战讲解视频，核心主题是 **多 Agent 协同设计的三大核心问题**。作者指出，多 Agent 协同是 AI PM 面试中最容易翻车的题目——比 RAG、Prompt 工程更容易被问倒。

核心框架一句话概括：**多 Agent 不是堆数量，是分工 + 通信 + 仲裁三件事。**

---

## 内容拆解

### ① 分工｜Supervisor 模式 (00:18)

| 角色 | 类比 | 职责 |
|------|------|------|
| **主 Agent** | 项目经理 | 只调度，不干活 |
| **子 Agent** | 专科员工 | 只做一件事，做到精 |

**真实案例：** 教育产品 4-Agent 架构
- 主 Agent：路由分发
- 子 Agent1：答疑
- 子 Agent2：批改
- 子 Agent3：推荐

> 结果：月活百万级 —— 这是大厂 AI PM 简历上最值钱的项目类型。

### ② 消息怎么传｜3 种模式 (01:26)

| 模式 | 适用场景 | 限制 |
|------|---------|------|
| **共享内存** | 小 demo | ≤ 3 个 Agent |
| **消息总线** | 生产环境首选 | LangGraph / CrewAI 同款 |
| **状态机** | 合规场景 | 金融 / 医疗 / 法律 |

### ③ 冲突怎么解｜3 种策略 (02:31)

典型场景：法务说"能签"，财务说"不能签"，谁说了算？

| 策略 | 适用场景 |
|------|---------|
| **主 Agent 仲裁** | 业务场景默认 |
| **投票机制** | 代码评审 / 内容审核 |
| **优先级规则** | 安全 Agent 否决一切 |

## 面试金句（原文）

被问"你们多 Agent 怎么设计的"：

1. **分工用 Supervisor 模式**
2. **消息默认消息总线（参考 LangGraph）**
3. **冲突分场景：业务上仲裁，多视角上投票，合规上优先级**

> 3 句答完，面试官立刻知道你真做过项目。

## AI 分析 & 延伸思考

### 为什么这个框架有价值？

1. **结构清晰**：用「分工→通信→仲裁」三维度拆解，覆盖了多 Agent 系统的全部设计空间
2. **分层递进**：从简单（共享内存）到复杂（状态机），从默认方案（仲裁）到特例（投票/优先级），给出实际工程中的推荐路径
3. **真实感强**：教育产品 4-Agent 案例和法务/财务冲突场景都来自真实经验，不是纸上谈兵

### 可以补充的维度

- **Agent 数量级考量**：3 个以内共享内存够用，10+ Agent 必须上消息总线，50+ 可能需要分层消息路由
- **容错设计**：子 Agent 超时或返回垃圾数据时，主 Agent 的重试/降级策略
- **可观测性**：多 Agent 系统的调试比单 Agent 难一个数量级，需要完整的 trace 链路
- **成本控制**：每个 Agent 调用 LLM 成本线性累加，如何在不牺牲质量的前提下降低 token 消耗

### 与业界框架对照

| 视频观点 | 对应业界实现 |
|---------|------------|
| Supervisor 模式 | LangGraph 的 `StateGraph` + `Supervisor` 节点 |
| 消息总线 | CrewAI 的 `Process.sequential` / `Process.hierarchical` |
| 共享内存 | AutoGen 的 `ConversableAgent` 即时对话 |
| 状态机 | LangGraph 的 `StateGraph` 状态流转控制 |

## 总结

这个视频用 4 分钟讲清了多 Agent 协同设计的核心框架，适合：

- 👉 **AI PM 求职者**：直接背面试金句，项目经验对答如流
- 👉 **技术负责人**：作为架构决策的 checklist（分工方案 → 通信模式 → 冲突策略）
