# 概念：Skill 设计模式

## 定义

Skill 设计模式是在实践中提炼的 4 种标准化组织方式，针对不同的任务场景选择不同的模式或组合，帮助开发者高效构建健壮的 Skill。

## 四种模式总览

### 模式一：模板驱动（Template-Driven）

**核心思路**：利用预定义模板严格约束输出格式。

| 维度 | 说明 |
|------|------|
| **适用场景** | 需要标准化输出的任务（周报、审查报告、API 文档） |
| **实现方式** | templates/ 目录 + SKILL.md 中的格式约束 |
| **价值** | 确保每次输出格式一致，减少格式修正 |

### 模式二：脚本增强（Script-Enhanced）

**核心思路**：将确定性计算逻辑封装为脚本，由大模型调用执行而非自行推导。

| 维度 | 说明 |
|------|------|
| **适用场景** | 财务计算、正则匹配、数据转换等确定性逻辑 |
| **实现方式** | scripts/ 目录中的脚本 + SKILL.md 路由调用 |
| **价值** | 比 LLM 推理更精准、更节省 Token、更具有复现性 |

> ⚠️ **经验法则**：如果发现自己在 SKILL.md 中编写公式让大模型运行计算，请立即停止——该逻辑应当被移至 scripts/ 中。

### 模式三：知识分层（Knowledge-Layered）

**核心思路**：依据使用频率对知识进行分层组织，遵循 **8/2 法则**（80% 的请求仅需 20% 的核心内容）。

| 层级 | 存储位置 | 内容 | 加载时机 |
|------|---------|------|---------|
| 高频核心 | SKILL.md 内联 | 常用流程、路由表 | 每次激活 |
| 中频参考 | reference/ | 详细规范、行业标准 | 条件触发 |
| 低频细节 | reference/ 深层 | 罕见边界情况 | 显式查询 |

### 模式四：工具隔离（Tool-Isolation）

**核心思路**：通过 `allowed-tools` 机制严格界定 Skill 的能力边界。

| 维度 | 说明 |
|------|------|
| **核心价值** | "禁止做什么" 比 "能做什么" 更关键 |
| **实现方式** | `allowed-tools` 白名单 |
| **适用场景** | 任何具有副作用或安全风险的 Skill |

> 这属于安全设计范畴——防止恶意代码或幻觉导致的越权操作。

## 模式选择决策

选择设计模式时考虑以下维度：

| 问题 | 判断 → 模式 |
|------|------------|
| 输出是否需要固定格式？ | 是 → 模板驱动 |
| 是否包含需要精确计算的操作？ | 是 → 脚本增强 |
| 知识量是否超过 500 行？ | 是 → 知识分层 |
| 是否涉及副作用或敏感操作？ | 是 → 工具隔离 |

四种模式**不互斥**——一个成熟的 Skill 通常同时采用多种模式。例如代码审查 Skill：模板驱动（统一输出格式）+ 知识分层（安全等级指南存放 reference/）+ 工具隔离（仅允许 Read/Grep/Glob）。
