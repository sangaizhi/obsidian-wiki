# 概念：渐进式披露

## 定义

渐进式披露（Progressive Disclosure）是 Skill 系统解决"海量知识如何精确匹配"问题的核心加载策略。它通过三层模型逐级展开信息，确保 Agent 在拥有大量 Skills 时，仍然能以极低的 Token 成本精确命中目标。

## 三层图书馆模型

类比图书馆的借阅流程：

```
浏览图书分类编目 → 提取目标书籍查阅图书目录 → 仅精读所需章节
```

Skills 系统的三层映射：

| 层级 | 图书馆类比 | Skill 系统对应 | 加载时机 | Token 成本 |
|------|-----------|---------------|---------|-----------|
| **第一层** | 分类编目 | 所有 Skill 的 `description` 字段 | 常驻注入上下文 | 极低（单行描述） |
| **第二层** | 图书目录 | `SKILL.md` 正文（路由器） | 按需加载 | 中等（数百 Token） |
| **第三层** | 精读章节 | `reference/`、`templates/`、`scripts/` | 仅当需要时 | 按需支付 |

> 每一层都是下一层的过滤器。第一层负责"知不知道有这个 Skill"，第二层负责"这个 Skill 能不能处理"，第三层负责"具体怎么处理"。

## Description 预算机制

### 预算公式

渐进式披露的第一层——所有 Skill 的 `description` 以常驻方式注入上下文，这意味着它们必须瓜分一个有限的 Token 预算。

Claude Code 规则：
- **总预算上限** = 上下文窗口总量的 **2%**
- 若未指定或计算异常，默认固定 **16,000 字符**
- **分配方式**：所有 Skill 平分，不是按需分配

```
单个 Skill 可用字符数 = 总预算 / Skill 总数
```

### 静默排除风险

如果某个 Skill 的 `description` 超过可用字符数，它将被 **静默排除**——Agent 完全不知道该 Skill 存在，扫描节点看不到，后续步骤也无法加载。没有任何警告或错误提示。

### 应对策略

| 技巧 | 机制 | 适用场景 |
|------|------|---------|
| 设置 `disable-model-invocation: true` | 该 Skill 的 description 不注入上下文，腾出预算 | 任务型 Skill、纯手动调用 |
| 运行 `/context` 诊断命令 | 查看是否有超出预算的 Skill 被静默移除 | 调试 Skill 莫名不触发 |
| 调整 `SLASH_COMMAND_TOOL_CHAR_BUDGET` | 手动扩大预算池 | Skill 数量多且质量高 |

### "少而精"架构原则

由于预算有限，Skill 设计应遵循"少而精"：

1. **合并同类 Skill**：将多个零碎的 Skill 合并为综合性 Skill
2. **隐藏内部工具**：纯内部调用的子任务标记 `disable-model-invocation: true`，减少预算占用
3. **关注 Token 投资回报率**：description 中的每个字符都是一笔投资，精准换取高效检索和准确执行
