# 概念：上下文工程

## 定义

上下文工程（Context Engineering）与 Prompt Engineering 的核心区别：
- **信息来源**：Prompt Engineering 的上下文主要来自用户输入；Context Engineering 处理的上下文绝大部分来自机器（工具）的输出
- **动态性**：Prompt Engineering 通常是静态的、一次性的；Context Engineering 是高度动态的，上下文在 Agent 整个运行周期中不断累积和变化

上下文工程 = 控制模型输入的信息管理策略，目标是在保证质量的同时提升稳定性并降低成本。

---

## 五大策略族（Context Engineering 核心框架）

| 策略 | 核心做法 | 代表 |
|------|---------|------|
| **Offload（卸载）** | 将中间产物、长文档和历史记录放到文件系统或外部存储 | Claude Code 的工具输出存档 |
| **Retrieve（检索）** | 只在当前任务需要时检索回来相关上下文 | RAG、Agent 记忆系统 |
| **Reduce（压缩）** | 可逆压缩优先：保留完整 JSONL、文件路径或结构化索引，再生成摘要 | Claude Code 五段流水线 |
| **Isolate（隔离）** | 子 Agent 隔离上下文窗口，独立处理子问题后汇总 | Claude Code Sub-agent |
| **Cache（缓存）** | 保持 prompt 前缀稳定，避免 KV cache 失效 | System Prompt 三段式 + Prompt Caching |

## 上下文压缩：六大 Agent 横向对比

| 产品 | 核心策略 | 特点 |
|------|---------|------|
| **Claude Code** | 五段流水线，按成本递增排列 | 便宜的本地操作先上，LLM 摘要兜底 |
| **Codex CLI** | 保留近期用户消息原文，其余替换为 handoff 摘要 | 用户说的话最准确，模型说的可以重写 |
| **OpenCode** | 时间戳标记隐藏 + 结构化摘要 + 回放最后一条用户消息 | 不真删，理论上可恢复 |
| **Cline** | /smol（/compact）生成摘要后在同一任务内接续 | 自动 + 手动双模式 |
| **Cursor** | 自动摘要 + 提示开新对话 + 历史可搜索 | 压缩后仍能回溯原始历史 |
| **Amp** | 不做递归压缩，用 /handoff 开新线程携带要点 | 长对话本身就是问题，换线程比压缩好 |
| **MemGPT / Letta** | 上下文 = RAM，历史 = 磁盘，Agent 自主换入换出 | 操作系统级的内存调度 |

### 第一代压缩的五大痛点

1. **悬崖式触发**：不溢出不动，一旦溢出全量出手——触发时质量已塌
2. **全量摘要丢细节**：变量名、函数签名、错误堆栈等关键信息被压没
3. **Token 估算粗糙**：`text.length / 3` 在中英混合场景下误差 30-50%
4. **不区分信息价值**：5000 行 grep 输出和 5000 token 关键诊断被同等对待
5. **用户内容被一刀切**：用户贴的代码和工具输出性质不同，但被一视同仁地压

### 第二代共识：分层 + 渐进

六家主流 Agent 不约而同走向"分层 + 渐进"路线。核心共识：
- **分层对待不同信息源**：用户消息 vs 工具输出 vs 模型输出分别处理
- **渐进触发而非悬崖式**：多级水位线，逐级压缩
- **可逆优先**：保留原文，只做摘要投影

### 四级水位线方案（MUR AI 实践）

面向云端多用户场景的增量压缩方案：
1. **L1（正常水位）**：无需压缩，正常运转
2. **L2（轻度压缩）**：裁剪冗余的工具输出
3. **L3（中度压缩）**：摘要化远古消息 + 裁剪老工具输出
4. **L4（重度压缩）**：全量摘要 + 读时投影

## 设计原则

- 只加载当前任务所需的信息
- 历史对话保留摘要，而不是保留完整流水账
- 工具结果只截取关键片段
- 任务完成后的中间信息及时归档，避免长期污染上下文
- **可逆压缩优先**：保留原始记录作为真相源，摘要只是索引

## 实用口诀

- 不用的信息不加载
- 记结论不记流水账
- 只看关键片段不看全文
- 保留原文，按需投影

## Context Engineering 实战（来自字节分享）

- **System Prompt 设计**：如何平衡覆盖面和精简度，避免"do list"综合征
- **上下文动态累积**：每次工具调用的输出都会改变下一轮推理的上下文质量
- **工具输出格式**：要求工具返回结构化数据（JSON），比自然语言更容易被 Agent 后续理解
- **延迟注入**：不要把所有上下文一次性加载，而是把信息放在工具结果里按需获取
