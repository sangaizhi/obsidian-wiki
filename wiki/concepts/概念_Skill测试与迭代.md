# 概念：Skill 测试与迭代

## 定义

Skill 测试是确保 Skill 健壮性的工程实践。通过触发、功能和性能三类测试，验证 Skill 是否能在正确时机激活并产生符合预期的输出。测试中发现的修正逻辑应直接写入 SKILL.md，形成持续改进的迭代闭环。

## 三类核心测试

### 一、触发测试

验证大模型判断是否调用的准确率。

| 维度 | 规范 |
|------|------|
| **应触发用例** | 准备 10 个应该触发 Skill 的问题 |
| **不应触发用例** | 准备 10 个不应触发 Skill 的问题 |
| **目标** | 相关任务触发率 ≥ **90%**，无关任务误触发率 ≤ **5%** |

> 触发测试直接验证 description 的质量。若未达标，回到 [[概念_Skill触发机制|触发机制]] 优化 description 的三要素。

### 二、功能测试

验证 Skill 加载后的执行质量。

| 检查要点 | 具体内容 |
|----------|---------|
| **输出格式** | 是否符合预期模板（如四要素是否完整） |
| **检查项覆盖** | 是否完整覆盖所有规定检查项（如安全/性能/质量三级） |
| **边界情况** | 边界输入是否得到妥善处理 |

### 三、性能对比

针对同一任务，分别在"有 Skill"和"无 Skill"状态下各执行 **5 次**，对比：

| 对比指标 | 说明 |
|----------|------|
| **Token 消耗量** | 有 Skill 应显著降低 Token（减少探索性工具调用） |
| **用户修正次数** | 有 Skill 应减少人工干预 |
| **最终输出质量** | 有 Skill 应更一致、更标准 |

## 迭代闭环

> 如果需要反复手动修正大模型的输出，就表明 SKILL.md 正文需要更新——将修正逻辑直接写入 SKILL.md，下次就不会发生同类错误。

```
测试 → 发现问题 → 修正写入 SKILL.md → 再测试 → 巩固
```

这与 Skill 的 Append-Mostly 维护策略一脉相承：每次踩坑就追加一条规则，让 Skill 持续进化。
