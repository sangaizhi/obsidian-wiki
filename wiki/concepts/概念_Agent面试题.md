# 概念：Agent 面试题（核心八问）

## 定义

本文梳理 Agent 大厂面试中最高频的八个核心问题，覆盖从基础概念到协议的完整知识体系。适合面试准备和系统性理解 Agent 技术主旋律。

---

## Q1: LLM 和 Agent 有什么区别？

### LLM 的四大弊端

| 弊端 | 说明 |
|------|------|
| **只会「说」不会「做」** | 能力被困在对话框里，无法操作外部系统 |
| **没有「记忆」** | 记忆仅限于当前上下文窗口，对话结束归零 |
| **不会用「工具」** | 不能上网搜索、查数据库、调 API |
| **不会「规划」** | 被动响应型，无法自主拆解任务、分步执行 |

### Agent 的定义

> **Agent 就是 LLM 在循环中自主使用工具的系统。** （LLM + Tools + Loop）

三个关键词：「LLM」是大脑、「工具」是手脚、「循环」是不断思考→行动→观察→再思考。

### Agent 如何解决 LLM 弊端

- **工具调用**：调用搜索引擎、数据库、API、代码执行器
- **记忆系统**：短期记忆（当前任务上下文）+ 长期记忆（跨对话保留）
- **标准化协议（MCP）**：统一工具接入方式
- **任务规划**：把大目标分解成多个小步骤逐步执行

### Agent 四大核心模块

1. **大脑（LLM）**：理解意图、推理判断、决定下一步
2. **规划模块**：拆解复杂任务为可执行步骤
3. **记忆模块**：存储和检索信息，保持长时间连贯
4. **工具模块**：Agent 的「手和脚」，跟外部世界互动

## Q2: Agent 和 Workflow 有什么区别？

| 维度 | Workflow | Agent |
|------|----------|-------|
| **定义** | LLM 和工具通过预定义代码路径编排的系统 | LLM 动态主导自身流程与工具调用的系统 |
| **控制权** | 在代码手里，流程确定 | 在 LLM 手里，行为动态 |
| **类比** | 工厂流水线——每个工位做什么都是提前设计好的 | 项目经理——老板只说目标，自己决定怎么做 |
| **可靠性** | 高，行为可预测、易定位 | 较低，决策路径不确定、难调试 |
| **Token 消耗** | 约 Agent 的 1/4 | 高（反复推理决策） |
| **灵活性** | 差 | 强，能适应变化 |

### 实战建议（Anthropic）

> **从最简单的方案开始，只在明确需要时才增加复杂度。**

- 步骤固定、高可靠性要求 → **Workflow**
- 开放式任务、无法预知步骤 → **Agent**
- 生产环境中最常见：**混合架构**（Workflow 控制主流程，复杂环节启动 Agent）

## Q3: Agent 有什么工作模式？

### 模式一：ReAct（边想边做）——最经典

Reasoning + Acting 的缩写。三步循环：
1. **思考（Thought）**：分析当前情况，决定下一步
2. **行动（Action）**：调用工具执行
3. **观察（Observation）**：查看工具返回结果

- 优点：透明可审计、灵活适应、通用性强
- 缺点：Token 消耗大、可能陷入循环

### 模式二：Plan-and-Execute（先想好再做）

- 第一阶段：Agent 先列出完整执行计划
- 第二阶段：逐步执行，不用每步重新全局推理
- 优点：省钱（Token 消耗约 ReAct 的 **1/5**）
- 缺点：不够灵活，可加入「重新规划检查点」

### 模式三：Reflection（做完再检查）

- **自我反思**：Agent 完成任务后切换「审查者」角色审视输出
- **双 Agent 对话**：一个生成 + 一个评审，来回迭代（类似 Code Review）
- 适合：代码生成、法律文书、学术论文等高要求场景

### 模式四：Multi-Agent（团队协作）

多个专业化 Agent 各司其职（规划、信息搜集、写代码、测试）。但 Anthropic 提醒：**不要过早引入多 Agent 架构**，很多时候单 Agent 就够用。

> 实际中往往组合使用。选择哪种模式，看任务特点和对灵活性、成本、质量的优先级。

## Q4: Function Call 是什么？

### 定义

Function Call 是 OpenAI 在 2023 年 6 月推出的能力——**让 LLM 不仅能生成文字，还能输出结构化指令告诉外部程序「我想调用某个函数，参数是这些」。**

### 四步流程

| 步骤 | 说明 |
|------|------|
| ① 定义函数 | 用 JSON Schema 描述工具名称、功能、参数 |
| ② 模型判断 | LLM 分析用户意图，自动决定调用哪个函数并提取参数 |
| ③ 执行函数 | **LLM 自己不执行**，由应用程序解析指令后实际调用 |
| ④ 生成回答 | 把返回结果发给 LLM，LLM 用自然语言回答 |

### 为什么重要

解决了两个核心问题：
- **「什么时候调用」的判断**：LLM 根据自然语言意图自动判断
- **「传什么参数」的提取**：从自然语言中提取结构化参数

### 与 Agent 的关系

**Function Call 是 Agent 的「原子操作」，Agent 是 Function Call 的「高级编排」。** Agent 在一个循环中反复使用 Function Call，每次观察结果再决定下一步。

## Q5: MCP 是什么协议？

### 问题背景：N × M 集成困境

每个 AI 应用 × 每个外部服务 = 定制集成爆炸。不同 LLM 厂商的 Function Call 格式还不统一。

### MCP 定义

**MCP（Model Context Protocol）= 「AI 界的 USB-C 接口」**。Anthropic 在 2024 年 11 月开源，提供统一标准让任何 AI 应用用同一种方式连接任何工具和数据源。

### 三层架构

| 角色 | 说明 |
|------|------|
| **MCP Host** | AI 应用（Claude Desktop、Cursor、自有 Agent） |
| **MCP Client** | 住在 Host 里，负责与 Server 通信的「翻译官」 |
| **MCP Server** | 对外暴露工具能力（GitHub Server、Slack Server 等） |

### 核心价值

将 N × M 集成问题变成 **N + M** 问题。工具可发现（启动时自动查询可用 MCP Server 及工具列表）。

## Q6: Skills 是什么？

### 定义

Skills 是**自然语言指令文件**（通常是 `SKILL.md`），教 Agent「在什么场景下、用什么方法、遵循什么规范」完成特定任务。

### 类比

| | 作用 | 比喻 |
|--|------|------|
| **MCP** | 解决「能做什么」 | 装满工具的厨房 |
| **Skills** | 解决「该怎么做」 | 菜谱——告诉 Agent 做红烧肉要先焯水再炒糖色 |

### 核心价值

将专业知识和最佳实践编码成可复用的模块。Skills 完全在 Agent 的上下文窗口内生效，不涉及外部调用。启动时 Agent 扫描可用 Skills，匹配后加载到上下文，Agent 在对应领域秒变专家。

---

## Q7: Function Call、MCP、Skills 有什么区别？

### 统一比喻（新员工入职）

| 概念 | 比喻 | 解决什么 |
|------|------|---------|
| **Function Call** | 「打电话的能力」 | LLM 怎么跟外部函数交互 |
| **MCP** | 「公司通讯录和电话系统」 | 怎么统一管理大量工具的集成 |
| **Skills** | 「岗位培训手册」 | Agent 怎么获得领域专业知识 |

### 分层关系

- **Function Call** 是底层基础（所有工具调用的原语）
- **MCP** 建立在 Function Call 之上，提供标准化包装
- **Skills** 在完全不同的维度——指导 Agent「什么时候调用什么工具、用什么策略」

三者**分层互补，不是竞争关系**。

## Q8: 什么是 A2A 协议？

### 为什么需要 A2A

MCP 解决 Agent→工具（竖向），但没有解决 Agent→Agent（横向）的协作问题。多 Agent 系统（跨团队/跨框架开发）需要互相发现、通信、委派任务。

### 定义

**A2A（Agent-to-Agent Protocol）** 是 Google 在 2025 年 4 月联合 50+ 合作伙伴发布的开放协议。基于 HTTP + JSON + SSE，无需新基础设施。

### 核心概念

| 概念 | 说明 |
|------|------|
| **Agent Card** | Agent 的「名片」，JSON 格式描述身份、能力、擅长领域 |
| **Task** | 协作围绕「任务」展开，有完整生命周期（创建→处理中→完成/失败） |
| **Message & Artifact** | 消息沟通过程信息，制品传递最终结果 |

### A2A 与 MCP 的关系

> **MCP 是「竖向」（Agent→工具），A2A 是「横向」（Agent→Agent），互补共存。**

标准格局：**Function Call 提供底层调用 → MCP 标准化 Agent-工具 → A2A 标准化 Agent-Agent**，三层各司其职。

## 全局脉络

```
LLM（纯大脑：会说不会做）
    ↓ +工具调用 +记忆 +规划
Agent（自主完成任务）
    ↓ 工作模式
ReAct / Plan-and-Execute / Reflection / Multi-Agent
    ↓ 底层技术栈
Function Call（原子操作）→ MCP（标准化连接）→ Skills（方法论层）
    ↓ 多 Agent 协作
A2A 协议（Agent 间通信标准）
```
